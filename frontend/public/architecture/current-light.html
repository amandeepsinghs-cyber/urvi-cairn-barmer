Urvi AI Agent · Architecture · Current (V 1.0 demo)

synthetic demo data
Single-Agent, Multi-Tool Hybrid Architecture: Natural spoken & typed language in (Gemini ADK / Live) → deterministic engineering physics, ML models & numeric-grounding guards underneath — best of both worlds with minimal hallucination.

As built and running today on Barmer Basin synthetic data (460 wells). Demo uses us-central1 for Gemini Live; data lakehouse sits in asia-south1.

① user asks ② web app calls the Urvi API ③ API hands the question to the agent ④ agent ↔ Gemini Flash ⑤ agent calls the analytics tools ⑥ tools read well data ⑦ answer + screen actions back to the browser Ⓐ–Ⓒ voice: audio → Live proxy ↔ Gemini Live → same tools
UsersAsset managers, production engineers and field supervisors. They use Urvi by mouse, typing or voice (Indian English by default; 15 Indian languages (Punjabi, Hindi, Gujarati, Marathi, Tamil, Telugu, ...) on request).
Esri imageryPublic satellite tiles behind the Barmer Basin map. Well and pad positions are synthetic.
Voice clientStreams microphone audio to the Live proxy over a WebSocket and plays Urvi's reply. Reconnects by itself with back-off (tab wake-up, network return) and retries voice every 20 s while in text mode (C-R10).
Urvi UIIndia → Barmer Basin → field → pad → well drill-down, the well panel and the docked Urvi agent.
Field map460 wells coloured Healthy / Needs attention / Not producing, pad flowlines, and an India view.
Hands-off controlPlain screen commands run in the browser with no model call; the agent can also send allow-listed screen actions (ui_control).
Answer canvasAgent answers open the matching view: charts, the completion diagram, comparisons, the printable pre-field well pack.
Gemini 3.8 LiveSpeech-to-speech model for voice. The demo runs in us-central1 because Gemini Live is not yet offered in India regions. One fixed voice (Aoede); the speech locale follows the language (Indian English by default). Numbers come only from tool results.
Gemini 3.8 FlashReasoning model for the typed agent: chooses tools, reads results, writes a short answer (D-13).
Gemini Live proxyServer-side WebSocket bridge between the browser and Gemini Live. Runs voice tool calls on the server; resumes the session on drops (6 tries with back-off) before falling back to text.
ADK agent runnerGoogle Agent Development Kit runner for chat. Routes the 5-level drill-down to tools; an after-model check masks any number that is not in a tool result.
Urvi APIPython API (FastAPI): wells, fields, documents, reports and /api/chat; also serves the web app.
Analytics & MLThe tools behind every answer: decline attribution, health, candidate ranking, next best action with top 3 and P(success). Shared by chat and voice; slow caches are warmed at startup so the first answer is quick. See docs/ml_recommendation_engine.md.
Data access layerOne repository interface over the landing tables: parquet baked into the image for the demo; the same API can read BigQuery Silver (parity-tested).
Document searchKeyword (TF-IDF) retrieval over the synthetic reports and SOP library; 29,136 chunks.
Field reportPrintable pre-field well pack and dossier; every digit traces to a tool return.
In-memory sessionsChat and voice sessions live in memory, hence one Cloud Run instance with session affinity (D-16).
Data generatorDeterministic generator for Mangala, Bhagyam, Aishwariya and Raageshwari (2021-10 → 2026-09). Also baked into the image.
Cloud StorageBucket gs://urvi-cairn-barmer-ai-agent-datalake storing synthetic landing parquets, PDFs, and Silver exports.
BigQuery BronzeDataset urvi_cairn_bronze (asia-south1): external tables over gs://urvi-cairn-barmer-ai-agent-datalake.
BigQuery SilverDataset urvi_cairn_silver (asia-south1): typed, de-duplicated tables loaded by MERGE.
BigQuery GoldDataset urvi_cairn_gold (asia-south1) built by Dataform: field KPIs and dossier facts.
Cloud BuildBuilds the image: web app, Python dependencies, document corpus and a self-check.
Artifact RegistryStores versioned images (V 1.0 = v1-4b8463d); rollback = shift traffic to an earlier revision.
Runtime service accountCloud Run runs as a dedicated service account; Vertex AI and BigQuery via Application Default Credentials.
Cloud LoggingCloud Run sends request and application logs to Cloud Logging automatically.
